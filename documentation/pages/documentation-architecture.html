Architecture Guide

Rules that preserve low coupling and high cohesion while extending ProjPortal.

Core Principles

Principle Practical rule
High cohesion Keep each class focused on one responsibility. Example: Student owns enrollment constraints, Teacher owns grading constraints.
Low coupling Depend on interfaces where possible, such as Observer, Researcher, ReportStrategy.
Orchestration in services If logic spans multiple entities, place it in AuthService, ResearchService, or UniversityDatabase.
UI thinness Menu classes in demo should gather input and call services/models; avoid embedding rule-heavy logic there.
Typed errors Add/throw custom exceptions from exceptions package for rule breaks instead of returning error strings.

Patterns Used

Pattern Where Benefit
Singleton services.UniversityDatabase Single shared in-memory state and centralized access.
Observer interfaces.Observable/Observer, services.AuthService, utils.SystemLogger Decouples event producers from event consumers.
Strategy interfaces.ReportStrategy, utils.SimpleStatisticsStrategy Allows reporting behavior swaps without changing core classes.
Decorator services.ResearcherDecorator Adds research behavior with minimal changes to existing model hierarchy.

Extension Checklist

  1. Decide if the feature is entity-local (models) or cross-entity (services).
  2. Add enum values instead of introducing repeated string literals.
  3. Add custom exception types for new rule violations.
  4. Update role menus only to invoke new use cases, not to host business logic.
